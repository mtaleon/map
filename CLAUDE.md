## Project Overview

Map coloring puzzle game built as a Progressive Web App (PWA) with Capacitor for native Android deployment. The game challenges users to fill map regions with 4 colors such that no adjacent regions share the same color.

## Architecture

### Core Game Logic (`core/`)
- **Board.js**: Region data structure and adjacency graph management
- **Game.js**: Game state, moves, undo/redo, timer, save/load, validation
- **Generator.js**: Procedural map generation using Delaunay triangulation
- **Solver.js**: Constraint satisfaction solver for hints and validation
- **events.js**: EventBus for decoupled component communication
- **constants.js**: Game constants (EVENTS, PRESETS, PALETTES, etc.)

### Platform Abstraction (`platform/`, `platforms/`)
The game uses a platform abstraction layer to support different rendering targets:
- **Interfaces** (`platform/`): IRenderer, IInput, IStorage define contracts
- **Implementations** (`platforms/web-dom/`): WebRenderer (SVG), WebInput (DOM events), WebStorage (localStorage)
- This design allows adding new platforms (e.g., Canvas, Native) without changing core logic

### Application Entry (`app.js`)
Wires together core logic, platform implementations, and event handlers. Initializes EventBus, Game, and platform-specific implementations.

### Event-Driven Flow
1. User interactions → Game logic updates
2. Game emits events via EventBus
3. Renderer subscribes to events and updates UI
4. All state changes flow through events (GAME_STARTED, BOARD_CHANGED, COLOR_SELECTED, VALIDATION_CHANGED, GAME_COMPLETED, etc.)

## Development Commands

### Local Development
```bash
# Build web assets to www/ directory
npm run build

# Run local dev server at http://localhost:8000
npm run dev

# Run E2E tests with Playwright
npm test
```

The build script copies files to `www/`: index.html, app.js, favicon.svg, manifest.json, sw.js, and directories core/, platform/, platforms/.

### Android Development
```bash
# Prepare and sync Android platform (generates android/ directory if needed)
npm run android:prepare

# Build debug APK
npm run android:build

# Build release APK
npm run android:release
```

**Important**: The `android/` directory is generated by Capacitor and excluded from git. Run `npx cap add android` first if it doesn't exist.

### Regenerating Android Icons
After modifying `favicon.svg`, regenerate Android app icons:
```bash
bash generate-icons.sh
```
This creates icons for all Android densities (mdpi through xxxhdpi) and updates the launcher foreground icons. The script uses macOS's built-in `qlmanage` and `sips` tools.

### Android CI Note
GitHub Actions CI uses Java 21 (see `.github/workflows/android.yml`), which matches Capacitor 8.x requirements. The Android Gradle Plugin 8.13.0 used by Capacitor requires Java 21.

## Testing

E2E tests in `e2e.test.mjs` use Playwright to verify:
- Map rendering (SVG regions)
- Color palette interaction
- Region filling and undo/redo
- Keyboard shortcuts
- Timer functionality
- Help/custom modals
- Preset switching
- Win condition detection

Tests expect hardcoded paths (e.g., `/opt/ws/map`, Chromium install path). Update these for your environment if needed.

## Adding a New Platform

To support a new rendering target (e.g., Canvas, Terminal UI):
1. Create directory: `platforms/<platform-name>/`
2. Implement: `Renderer.js` (IRenderer), `Input.js` (IInput), `Storage.js` (IStorage)
3. Update `app.js` to conditionally instantiate the new platform implementation
4. Core game logic requires no changes

## Common Patterns

- **Region Selection**: User clicks → Input handler → Game.selectRegion() → BOARD_CHANGED event → Renderer updates fill
- **Undo/Redo**: Game maintains undoStack/redoStack of board snapshots, emits BOARD_CHANGED to sync UI
- **Save/Load**: Game serializes state to localStorage via Storage interface on every change (debounced)
- **Validation**: Board.validateAll() checks all regions for conflicts, updates isValid flag
- **Completion**: When remainingCount() === 0 and all valid, Game emits GAME_COMPLETED with stats
